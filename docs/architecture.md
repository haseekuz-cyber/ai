# Архитектура

## Рабочее пространство

Controller и Worker работают в одной Windows-учётной записи. Пространство AI ограничено вторым монитором и выбранным окном. Отдельная ОС или вторая Windows-сессия не требуются.

```text
Пользователь, основной монитор        AI, второй монитор
┌─────────────────────────┐          ┌────────────────────────────┐
│ физическая мышь         │          │ выбранное окно приложения │
│ обычная клавиатура      │          │ синий AI-курсор           │
└─────────────────────────┘          └─────────────┬──────────────┘
                                                  │
                    ┌─────────────────────────────┴─────────────┐
                    │ Worker                                  │
                    │ UI Automation + Direct Window messages  │
                    │ снимок HWND + подтверждения + аудит     │
                    └────────────────┬──────────────────────────┘
                                     │ loopback
                    ┌────────────────▼──────────────────────────┐
                    │ LM Studio · Qwen3-VL 8B                  │
                    └───────────────────────────────────────────┘
```

> Актуальный целевой контракт и этапы внедрения находятся в [JARVIS-2.0.md](JARVIS-2.0.md). Этот документ описывает низкоуровневый Windows-контур.

## Единый JARVIS (этапы 1–2)

```text
Пользователь / панель
        │ одна цель и один sessionId
        ▼
AgentSession → append-only EventLog → SessionReducer → ContextCompiler
        │                                             │
        └─────────────────────────────────────────────▼
                                      одна активная модель LM Studio
                                                    │
                                             одно решение
                                                    ▼
ToolRegistry → Policy + Idempotency Ledger → Tool → проверяемый результат
                                                    │
                                                    └──→ EventLog
```

- `SessionEventLog` является источником истины; модель не владеет состоянием сессии.
- Контекст закрепляет цель, критерии, исправления, последнее наблюдение и последний результат, а затем добавляет только помещающиеся события.
- Read-only инструменты могут выполняться параллельно, но записываются в порядке `dispatchIndex`.
- Каждый эффект имеет `toolInvocationId`; завершённый эффект не повторяется после сбоя, неопределённый `at_most_once` переводится в `indeterminate`.
- Обычная задача, автономный режим и программист используют одинаковый `AgentEngine`, меняется только явный режим и набор доступных инструментов.
- Старые mission/teacher маршруты временно остаются для демонстраций и сравнения, но новый интерфейс задач использует `/agent/sessions/*`.

## Rollout gate

`AI_WORKSTATION_UNIFIED_AGENT=1` открывает unified API для оценки. `AI_WORKSTATION_AGENT_MUTATIONS=1` лишь запрашивает изменяющие инструменты; Worker разрешает их, только если `latest-report.json`:

- относится к текущему `activeModel` и protocol version 1;
- содержит ровно 100 structured, 30 UI, 10 code и хотя бы один session-isolation кейс;
- достигает 98/100 structured с первой попытки и 100/100 после одного repair;
- достигает 27/30 выбора UI-инструмента и 24/30 grounding;
- достигает 7/10 определения владельца дефекта и 6/10 проходящих code-candidate;
- не содержит ни одного загрязнения новой сессии старой целью.

Benchmark читает только явно перечисленные в манифесте кадры, диапазоны событий и ErrorPacket, не выполняет UI-эффекты и не применяет код. Поля gate и путь отчёта видны в `/health`.

## Цикл задачи

1. Worker непрерывно строит дешёвую карту изменений всего назначенного AI-дисплея; перед решением сохраняет свежий ключевой кадр.
2. Локальная модель предлагает следующий шаг или короткий мини-план и уровень риска.
3. Координаты привязываются к текущему UI-элементу, если он доступен.
4. Изменяющий шаг показывается пользователю и ждёт подтверждения.
5. Worker отправляет действие прямо целевому окну, не двигая системный курсор.
6. Событийный слой и UIA сначала проверяют результат без модели. VLM вызывается только при визуальной неоднозначности; при расхождении очередь мини-плана сбрасывается.

## Обучение показом

Режим наблюдения видит весь назначенный AI-монитор и отделяет управляющие клики админ-панели от полезных действий в приложениях. Демонстрации преобразуются в причинные шаги навыка. Для каждого шага сохраняются устойчивый селектор, координаты относительно фактического окна, кадры до/после, клавиши и модификаторы, семантика траектории, ожидаемый результат и способ проверки. Парольные поля исключаются.

## Безопасность

- окно должно находиться на назначенном втором мониторе;
- терминалы, Codex и ChatGPT запрещены как цели;
- физический системный курсор не используется;
- внешние приложения получают повышенный риск;
- низкая уверенность модели блокирует действие;
- аварийная остановка блокирует UIA, Direct Window, задачи и навыки;
- журнал действий не сохраняет вводимый текст.
