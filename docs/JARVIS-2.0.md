# JARVIS 2.0 — зафиксированный контракт

Этот документ не является обещанием, что все пункты уже готовы. Он разделяет доказанную реализацию, следующий этап и критерии, по которым система считается работающей. Он нужен, чтобы новые исправления не уводили проект обратно к повторению координат или к одному приложению.

## Цель

JARVIS — локальный учитель и управляющий слой универсального Windows-агента. Worker должен осваивать произвольные видимые программы через UI, учиться по демонстрациям и исправлениям человека, адаптироваться к перемещённым элементам и проверять фактический результат.

Ни JARVIS, ни Worker не являются отдельной обученной нейросетью. Это модель-независимая система вокруг сменяемых локальных моделей. Опыт, навыки, принципы и проверки должны сохраняться при замене Qwen на другую модель.

## Неподвижные инварианты

1. Наблюдение видит весь назначенный AI-монитор, включая модальные окна и смену приложений. Исполнение остаётся ограничено свежей видимой поверхностью выбранной программы.
2. Демонстрация сохраняет не только координаты: цель, объект, до/после, модификаторы, траекторию, ожидаемый результат, восстановление и финальный референс.
3. Траектория классифицируется как `exact`, `adaptive`, `optional` или `replaceable`. Она анализируется, а не воспроизводится вслепую.
4. Успех определяется наблюдаемым результатом. `timeout`, отсутствие изменения и словесная уверенность модели не являются успехом.
5. Ошибка не становится знанием. Путь опыта: `raw → interpreted → verified → training_approved`.
6. Задача пользователя не сохраняется как универсальный принцип. В память попадает только переносимый приём или явное предпочтение.
7. QLoRA не запускается автоматически. Нужны разнообразные подтверждённые примеры и отдельное сравнение адаптера.
8. Кодовая модель не изменяет рабочую версию напрямую.

## Основной цикл UI

```text
цель пользователя
  → непрерывный дешёвый observer (кадры + diff + UIA)
  → актуальная карта UI
  → поиск подходящего проверенного навыка / RAG
  → Planner формирует 1 действие или мини-план
  → grounding по свежему состоянию
  → Worker выполняет одно физическое действие
  → дешёвая проверка события/UIA
  → VLM-проверка только при неоднозначности
  → продолжение очереди или новое планирование
  → Episode + оценка человека
```

Мини-план никогда не исполняется целиком вслепую. Перед каждым физическим действием проверяются окно, документ, поверхность и семантическая цель; после каждого действия проверяется локальный результат. Любое расхождение сбрасывает остаток очереди.

## Обучение демонстрацией

```text
события клавиатуры/мыши + важные кадры
  → удаление управляющих кликов админ-панели
  → группировка в логические действия
  → причинная интерпретация JARVIS
  → пользователь подтверждает или исправляет смысл
  → исполнимый граф навыка
  → адаптивный повтор
  → сравнение каждого шага и финала с референсом
  → повышение доверия только после успеха
```

Если пользователь действует быстрее фонового интервала, кадры фиксируются по событиям: перед нажатием, во время drag, после отпускания, после Enter и после появления/исчезновения окна. Фоновая частота остаётся низкой, чтобы не нагружать CPU и диск.

## Долговременное знание

```text
Raw events
  → Episode (что произошло)
  → Verified skill (как повторить и проверить)
  → Principle (переносимое правило)
  → Training example (только подтверждённая пара)
```

- RAG хранит документацию программ, сочетания клавиш, типовые операции и известные ошибки.
- Skills хранят исполнимые графы конкретных приёмов.
- Principles хранят короткие переносимые правила.
- Dataset содержит снимок состояния, выбранное действие, обязательные модификаторы, результат, исправление и версии модели/кода.

## Самоулучшение Worker

```text
ошибка
  → обезличенный ErrorPacket + fingerprint
  → выбор вмешательства
  → воспроизводящий тест
  → минимальный patch в отдельной копии
  → тесты исходной версии
  → тесты кандидата
  → сравнение без регрессий
  → явное подтверждение пользователя
  → применение + резервная копия
  → canary/eval
  → принятие или откат
```

Маршрутизация вмешательств:

| Наблюдение | Правильное вмешательство |
|---|---|
| crash, PowerShell/capture, JSON schema, bounds, state machine | код + regression test |
| неизвестная операция программы | RAG / документация |
| повторяемая последовательность в одной программе | проверенный skill |
| одинаковая смысловая ошибка в разных программах | prompt/policy + eval |
| явное предпочтение человека | memory |
| подтверждённое исправление шага | training example |
| сотни разнообразных проверенных примеров | QLoRA-кандидат |

## Локальные модели и VRAM

Worker поддерживает роли через переменные окружения:

- `AI_WORKSTATION_VISION_MODEL`
- `AI_WORKSTATION_PLANNER_MODEL`
- `AI_WORKSTATION_CRITIC_MODEL`
- `AI_WORKSTATION_CODER_MODEL`
- `AI_WORKSTATION_EMBEDDING_MODEL`

ModelBroker сериализует тяжёлые запросы и публикует активную модель/очередь в `/health`. На RTX 3060 12 GB по умолчанию все тяжёлые роли могут указывать на одну текущую Qwen3-VL. Отдельная coding-модель подключается после локального A/B-теста; несколько тяжёлых моделей одновременно в VRAM не требуются.

Стандартный контекст запуска — 12 288 токенов: этого достаточно для двух ключевых кадров и компактной карты UI, но промпты всё равно ограничиваются и сначала теряют старую/необязательную информацию. GPU offload остаётся `max`; искусственного лимита загрузки GPU Worker не вводит.

## Что выполняется постоянно, событийно и в фоне

| Режим | Работа |
|---|---|
| Постоянно, дёшево | захват малой карты изменений, окно/документ, Stop, карта UI |
| По событию | ключевой кадр, re-grounding, действие, postcondition, сброс мини-плана |
| По неопределённости | VLM grounding, визуальная проверка, Critic |
| После миссии | компиляция Episode, сравнение с референсом, обновление доверия |
| В фоне и вручную | RAG-индексация, replay-eval, dataset export, QLoRA, coding candidate |

## Критерий готовности первого вертикального сценария

Один показанный навык должен в 10 контролируемых попытках:

- не менее 9 раз правильно определить цель;
- не менее 8 раз выполнить её после перемещения или изменения размера окна;
- сохранить Ctrl/Shift/Alt и важную траекторию;
- не перейти к случайной автономной цели;
- сравнить финал с пользовательским референсом;
- объяснить расхождение;
- принять текстовую коррекцию или мини-демонстрацию конкретного шага;
- успешно повторить исправленную версию.

## Состояние реализации на 2026-08-14

Доказано тестами: событийный observer с fallback, свежий снимок перед действием, мини-планы с семантическим rebind, проверка после каждого действия, модификаторы и траектория, пошаговые кадры, финальный референс, коррекция шага, модель-независимая память, structured JSON retry, ErrorPacket, маршрутизатор вмешательств, ModelBroker, сравнение baseline/candidate, отдельная копия, явное применение и откат.

Ещё требует живой проверки: стабильное 8/10 повторение одного навыка в реальной программе, качество причинной интерпретации быстрых демонстраций, полноценная RAG-база хотя бы одной программы, A/B альтернативной vision-модели и canary-сравнение новой версии Worker на записанном replay-наборе.
