# Зафиксированное направление: Agent Reach и быстрое обучение показом

Статус: утверждено как следующее направление, но установка и реализация отложены до следующей идеи пользователя.

## Роли компонентов

- Agent Reach устанавливается отдельно для Codex и для JARVIS как слой поиска и получения знаний из интернета.
- JARVIS использует найденные официальные материалы, GitHub-код и видеоуроки, проверяет источники и превращает сведения в план для Worker.
- Worker остаётся универсальным исполнителем Windows UI: наблюдает экран, выполняет план и проверяет фактический результат.
- Agent Reach не заменяет Qwen/VLM, наблюдение экрана, управление мышью и клавиатурой, память навыков или обучение по демонстрации.

Желаемый обмен:

`неизвестное состояние или ошибка -> JARVIS -> Agent Reach -> доказательные источники -> проверяемая гипотеза и план -> Worker -> наблюдение результата -> подтверждённый опыт`

План, передаваемый Worker, должен содержать цель, начальные условия, приложение, последовательность действий, важные модификаторы и траектории, ожидаемый результат каждого шага, способ проверки, восстановление и ссылки на источники. Нельзя превращать найденный текст в навык до успешной проверки в интерфейсе.

## Проблема последней быстрой демонстрации

Наблюдение распознало цель «Создать новый документ в CorelDRAW», сохранило один причинный эпизод и не получило подсказок учителя. Финальный результат после последней полезной команды не был снят, поэтому демонстрация не является подтверждённым исполнимым навыком.

Вероятная причина: пользователь выполнял действия быстрее частоты визуального наблюдения, а остановка записи произошла до отдельного устойчивого финального кадра. Сырые события могли сохраниться, но их смысл и результат не были связаны доказательством «до -> действие -> после».

## Обязательные требования к будущему исправлению

- ввод мыши и клавиатуры фиксируется событийно, без зависимости от частоты кадров;
- важный кадр снимается непосредственно перед действием и сразу после него;
- частые действия объединяются в логическую операцию, но не теряются;
- при завершении показа запись сначала ждёт стабилизации интерфейса и снимает финальный результат, а клик по панели «Завершить» не становится частью навыка;
- если финального результата нет, JARVIS честно сообщает, что понял цель, но не подтвердил результат;
- пользователь может попросить «повтори, что понял» и затем подтвердить или исправить понимание;
- быстрое выполнение пользователя должно быть допустимым: система сама увеличивает плотность фиксации около ввода и значимых изменений;
- пользователь оценивает результат положительно или отрицательно; дословное описание каждого действия не требуется.

## Следующий шаг

Сначала выслушать дополнительную идею пользователя по ускорению улучшения. После этого выбрать окончательную схему и только затем устанавливать Agent Reach или изменять Worker/JARVIS.
